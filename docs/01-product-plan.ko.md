# 기획과 시장 검토 — 2026-09-09

## 추천: Mimamori Ops

일본 소규모 웹 제작사가 고객 사이트의 장애를 확인하고 고객에게 설명하는 시간을 줄이는 운영 도구. 초기에는 담당자가 사용하는 CLI와 일본어 Markdown 보고서로 제공한다. 인프라 취업 포트폴리오가 1순위, 유료 수요 검증이 2순위다.

프로젝트가 서류 합격을 보장하거나 회사의 실무 경력을 대체하지는 않는다. 다만 설계 이유, 테스트, 로그, 장애 대응, 비용 계산을 실제 산출물로 설명할 근거가 된다. AI가 구현한 부분과 사용자가 직접 이해·검증한 부분을 구분한다.

## 수익 모델 가설

- 고객: 5~20개 소규모 사이트를 관리하는 일본 웹 제작사. 첫 MVP는 최대 5개 사이트.
- 가치: 장애 시각·관측 오류·복구 여부를 정리하고, 월간 보고서 초안 작성 시간을 절약.
- 실험 가격: 제작사당 월 1,980엔(5개 사이트), 월 4,980엔(보고서 검토·인수인계 지원 포함). **확인된 시장 가격이나 매출 전망이 아닌 인터뷰용 가설**.
- 월 1,980엔 × 10개사 = 매출 19,800엔이라는 단순 시나리오. 세금·결제 수수료·인건비·클라우드 비용·고객 획득 비용을 제외하지 않은 수치이며, 현재 고객과 매출은 0.
- 관측은 자동화하되 원인·책임·대응 완료를 AI가 추측해 쓰지 않는다. 초기 보고서는 사실 템플릿으로 생성하고 담당자가 검토한다.
- 24시간 사람의 장애 대응이나 가용성 SLA를 초기 상품에 약속하지 않는다.

## 2주 수요 검증 계획 — 연락·영업은 아직 실행하지 않음

1. 제작사 담당자 5명에게 최근 장애 연락 방식, 월 보고서 소요 시간, 기존 모니터링 도구를 질문.
2. 모의 보고서를 보여주고 반드시 필요한 항목 3개, 현재 대안, 유료 전환 조건 확인.
3. 동의한 2개사의 본인 소유/관리 사이트로 제한된 파일럿. 모니터링 동의·보고 대상 확인.
4. '보고 시간이 월 30분 이상 줄었는가', '최소 1곳이 유료 파일럿을 선택하는가'로 판단. 이는 성공 기준 제안이며 결과는 미확인.
5. 가치가 없으면 기능을 늘리기 전에 고객 문제를 다시 정의. 무료 경쟁 도구에 보고 기능을 보완하는 방향도 비교.

## 범위

이번 로컬 납품: HTTPS 점검, DNS/IP 제한, TLS 검증·잔여일 기록, 연속 실패/복구 상태 관리, 알림 재시도용 상태, 일본어 보고서, 장애 데모, 테스트, Terraform, CI/CD 정의, 운영·학습 문서.

고객 판매 전 후속 검증: 실 AWS 관측과 알림 수신, 7일 운영, 실제 사용자 피드백, 고객별 접근 제어, 보관 정책 합의, 청구·계약·지원 범위. 결제·회원가입·다중 고객 웹 콘솔·실시간 SLA는 이번 MVP에 포함하지 않는다.

# SAA 학습과 면접 설명

## 이 프로젝트가 보여줄 것

미경험 중도 지원에서는 '서비스를 많이 사용했다'보다 '요구사항을 이해하고, 실패를 구분하고, 사실을 기록하고, 다음 담당자에게 설명한다'를 보여주는 데 초점을 둔다. 개인 프로젝트는 상업 환경에서 맡은 실무 경력이 아니다.

일본 대기업·IT기업·외자계라는 회사 분류만으로 난이도를 판단하지 않는다. 공고의 미경험 지원 조건, Linux/네트워크 요구, 고객 대응 언어, 온콜·교대, 비자 지원, 최초 배치 업무를 따로 확인한다. 초기 지원 직무는 인프라 운영·운용보수·클라우드 지원·사내 IT 지원 등과 연결하기 쉽고, 설계 구축 즉시전력·SRE 경험직 충족을 주장하지 않는다.

## SAA-C03에 연결하기

[공식 시험 가이드](https://docs.aws.amazon.com/aws-certification/latest/solutions-architect-associate-03/solutions-architect-associate-03.html)의 네 영역은 보안 30%, 복원력 26%, 성능 24%, 비용 20%다(2026-09-09 확인). 이 프로젝트만으로 모든 출제 범위를 학습하거나 합격을 보장할 수는 없다.

| 영역 | 이 프로젝트에서 설명할 문제 | 추가로 공부할 범위 |
|---|---|---|
| 보안 30% | IAM 실행 역할과 배포 역할 차이, TLS 검증, 공개 IP 제한, OIDC 신뢰 범위 | VPC·서브넷·SG/NACL, KMS 키 정책, S3 권한·암호화, Organizations |
| 복원력 26% | 연속 실패 판정, 조건부 저장, 중복 이벤트, SNS 재시도, DLQ, 롤백 | Multi-AZ와 Multi-Region, RDS failover, 백업·복원, RTO/RPO, SQS 독립 worker |
| 성능 24% | 요청 간격, Lambda 메모리/Duration, DynamoDB 용량·키 설계, 작은 데이터 보관 | EC2 선택, Auto Scaling/ALB, CloudFront, ElastiCache, RDS/read replica |
| 비용 20% | 서버리스 선택 이유, provisioned/on-demand 차이, 무료량 공유, 로그/알람 수 | Savings Plans/RI/Spot, S3 계층, NAT·전송 비용, 비용 비교 문제 |

## 4주 실습 계획 — 하루 60~90분 제안

| 주 | 직접 수행할 일 | 면접용 증거 | 완료 조건 |
|---|---|---|---|
| 1 | HTTP/DNS/TLS 흐름 이해, 로컬 demo, 실패 원인별 테스트 읽기 | 본인 언어의 구성도·용어 설명 | 화면 없이 한 요청의 흐름을 3분 설명 |
| 2 | SQLite 상태 확인, 테스트 1개를 직접 수정해 예상/실제 비교, 브랜치와 diff 검토 | 본인 작성 변경 이유·리뷰 메모 | 실패 1회와 2회의 차이, 중복 처리 이유 설명 |
| 3 | 승인된 계정에서 1개 대상 AWS 파일럿, IAM·로그·SNS·오류 확인 | 익명화한 실행/수신/비용 기록 | 정상·실패·복구와 감시 중단을 각각 구분 |
| 4 | 7일 관측, 장애 훈련, 롤백·회고, SAA 부족 영역 문제 풀이 | 관측 보고서·incident report·비용 비교 | 처음 가설, 확인한 사실, 남은 한계를 설명 |

3~4주 단계는 실제 승인이 있은 뒤 수행한다. 현재 AWS 운영·사용자 실습 완료로 체크하지 않는다.

## 설명하는 순서

고객 문제 → 작은 규모 조건 → 구조 선택 → 실패 시 동작 → 확인 근거 → 한계와 개선 순서로 말한다. 처음부터 AWS 서비스 이름을 나열하지 않는다.

### 현재 상태에서의 소개 예시

日本の小規模なWeb制作会社を想定し、サイトの監視結果と障害の引継ぎ情報を整理する個人プロジェクトを、AI支援で試作しています。
일본 소규모 웹 제작사를 가정해 사이트 감시 결과와 장애 인수인계 정보를 정리하는 개인 프로젝트를 AI의 도움으로 시제품으로 만들고 있습니다.

現時点ではローカル実装と自動テストの段階で、AWSでの継続運用や顧客利用はまだ行っていません。
현재는 로컬 구현과 자동 테스트 단계이며 AWS 지속 운영이나 고객 이용은 아직 진행하지 않았습니다.

今後、自分で設計理由と障害時の動作を確認し、実施した検証だけを説明できるように学習を進めます。
앞으로 제가 직접 설계 이유와 장애 시 동작을 확인하며, 실제 수행한 검증만 설명할 수 있도록 학습하겠습니다.

### 직접 학습한 뒤 답할 연습 문장

以下は練習用の説明です。実際に理解・検証した範囲に合わせて使います。
아래는 연습용 설명입니다. 실제로 이해하고 검증한 범위에 맞춰 사용합니다.

**Q1. 왜 Lambda인가요?**

5分ごとの小さな処理なので、常時稼働するサーバーより運用負担を抑えやすいLambdaを選びました。
5분마다 실행하는 작은 처리라서 상시 가동 서버보다 운영 부담을 줄이기 쉬운 Lambda를 선택했습니다.

ただし、長時間の処理や細かいOS設定が必要なら、EC2なども比較します。
다만 장시간 처리나 세부 OS 설정이 필요하면 EC2 등도 비교합니다.

**Q2. DNS·TLS·HTTP의 차이는 무엇인가요?**

DNSで接続先のIPアドレスを確認し、TLSで暗号化と接続先の確認を行い、HTTPで応答コードを確認します。
DNS로 접속할 IP를 확인하고, TLS로 암호화와 접속 대상 검증을 하며, HTTP로 응답 코드를 확인합니다.

**Q3. 왜 실패 한 번에 알리지 않나요?**

一時的な通信エラーによる通知を減らすため、連続2回の失敗で障害と判定します。その分、検知までの時間は長くなります。
일시적인 통신 오류 알림을 줄이기 위해 연속 2회 실패하면 장애로 판정합니다. 그만큼 감지까지 걸리는 시간은 길어집니다.

**Q4. HTTP 503이면 무엇이 원인인가요?**

503だけでは原因を確定できません。対象範囲、直近の変更、アプリケーションとインフラのログを確認し、確認済みの事実を担当者に共有します。
503만으로는 원인을 확정할 수 없습니다. 대상 범위, 최근 변경, 애플리케이션과 인프라 로그를 확인하고 확인한 사실을 담당자에게 공유합니다.

**Q5. 감시 프로그램 자체가 멈추면요?**

Lambdaのエラーだけでなく、対象ごとの確認完了ログが一定時間ない場合もCloudWatchで検知する設計です。
Lambda 오류뿐 아니라 대상별 확인 완료 로그가 일정 시간 없는 경우도 CloudWatch에서 감지하는 설계입니다.

**Q6. 같은 알림이 중복될 수 있나요?**

観測データの重複保存は条件付きで防ぎます。ただし、通知送信の直後に処理が停止すると同じ通知IDが再送される可能性があります。
관측 데이터의 중복 저장은 조건부 처리로 막습니다. 다만 알림 전송 직후 처리가 중단되면 같은 알림 ID가 재전송될 수 있습니다.

**Q7. 왜 데이터베이스가 필요한가요?**

前回の結果と連続失敗回数を次の実行でも使うためです。Lambdaのメモリだけでは次の実行に状態が残る保証がありません。
이전 결과와 연속 실패 횟수를 다음 실행에서도 사용하기 위해서입니다. Lambda 메모리만으로는 다음 실행에 상태가 남는다는 보장이 없습니다.

**Q8. CI와 CD는 무엇이 다른가요?**

CIでは変更のテストと検証を行い、CDでは検証した成果物を承認された環境に反映します。GitHub上の実行結果は、実際に動かしてから実績として記録します。
CI에서는 변경을 테스트·검증하고 CD에서는 검증된 산출물을 승인된 환경에 반영합니다. GitHub 실행 결과는 실제로 실행한 후 실적으로 기록합니다.

**Q9. 무료라고 확신할 수 있나요?**

無料枠内を目指した小規模な設計ですが、アカウント全体の利用量やタイムアウト、再試行によって課金される可能性があります。実際の利用量と予算アラートを確認します。
무료 범위를 목표로 한 작은 설계지만 계정 전체 사용량이나 타임아웃·재시도로 과금될 수 있습니다. 실제 사용량과 예산 알림을 확인합니다.

**Q10. AI를 얼마나 사용했나요?**

コードと文書の作成にはAIを利用しています。自分だけで実装したとは説明せず、自分が理解し、実際に確認した設計や検証内容を具体的に説明します。
코드와 문서 작성에 AI를 사용하고 있습니다. 혼자 구현했다고 설명하지 않고, 제가 이해하고 실제로 확인한 설계와 검증 내용을 구체적으로 설명합니다.

**Q11. 100% 가동률을 증명했나요?**

いいえ。このレポートは5分ごとの観測成功率です。観測していない時間や確認の間に発生した障害まで保証するものではありません。
아닙니다. 이 보고서는 5분마다 관측한 성공률입니다. 관측하지 않은 시간이나 확인 사이에 발생한 장애까지 보장하는 것은 아닙니다.

**Q12. 실무와 다른 점은요?**

個人の学習用MVPであり、顧客対応や商用SLA、複数人での運用実績はまだありません。今後は許可された小規模な環境で運用し、記録と改善を重ねる必要があります。
개인 학습용 MVP이며 고객 대응·상용 SLA·여러 사람의 운영 실적은 아직 없습니다. 앞으로 허가된 작은 환경에서 운영하며 기록하고 개선할 필요가 있습니다.

## Linux·네트워크 보완 실습

사용자가 이미 가진 Linux/WSL 환경에서만 수행한다. 이번 작업에서 OS 기능이나 VM을 새로 설치하지 않았다. 학습 대상 URL은 소유/허가된 사이트로 바꾼다.

```bash
getent hosts YOUR-OWNED-DOMAIN
curl -I --max-time 5 https://YOUR-OWNED-DOMAIN/
openssl s_client -connect YOUR-OWNED-DOMAIN:443 -servername YOUR-OWNED-DOMAIN </dev/null
ss -lnt
df -h
free -m
```

각 명령에서 '무엇을 확인하는가, 정상 출력은 무엇인가, 이것만으로 무엇은 알 수 없는가'를 한 문장씩 적는다. EC2/VPC/ALB/RDS를 직접 배포하는 확장 실습은 SAA 학습에 유용하지만 비용 검토 후 짧은 시간에 생성·검증·삭제하는 별도 과제로 진행한다.
